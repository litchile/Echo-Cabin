# Echo Cabin Sound Creation UI Shell

**文档版本：** V0.1  
**文档状态：** 待 Figma 结构设计与确认  
**适用阶段：** Prototype 阶段 3 与阶段 4 之间的界面架构 Checkpoint

## 1. Checkpoint 目标

本 Checkpoint 只冻结角色创建、声音来源选择和角色切换的界面结构，使阶段 4 可以在明确的玩家流程和状态模型上实现录音、本地导入、试听与保存。

本轮输出以 Figma 低保真到中保真线框和可点击流程为主，不制作正式品牌视觉，也不改变已经冻结的角色数据、draft、active character、容量、出生点和切换规则。

## 2. 设计原则

- 主场景在正常探索期间尽量保持干净；
- 右上角只保留轻量的当前角色头像或角色入口，不长期悬挂大型管理面板；
- 创建角色时使用独立居中卡片或适合移动端的底部抽屉；
- 录音和导入进入明确、临时的操作层，完成或取消后返回场景；
- 角色切换使用头像列表和清晰的当前角色标识，不使用后台式文字管理面板；
- 提示采用温暖、轻量、半透明的游戏 UI 语言，避免深黑色控制台观感；
- 桌面与移动端共享同一状态结构，布局可以按屏幕尺寸调整；
- 所有失败状态都必须提供明确的恢复动作，不能只显示错误文本。

## 3. 必须覆盖的界面与状态

### 3.1 场景入口与角色身份

1. 首次进入且尚无角色时的创建角色入口；
2. 已存在角色时的轻量新增角色入口；
3. 名字输入；
4. 预设形象选择；
5. 返回、取消及放弃 draft 的确认；
6. 最多 4 个角色的容量反馈。

### 3.2 声音来源选择

玩家完成名字和形象后，进入声音来源二选一：

- 现场录音；
- 从本地设备导入。

没有有效且已主动保存的声音时，不提供完成角色创建的绕过入口。

### 3.3 现场录音状态

Figma 流程至少覆盖：

1. 录音说明与主动开始入口；
2. 请求麦克风权限前的说明；
3. 录音中状态，包括明确的进行中反馈和停止操作；
4. 录音完成；
5. 试听；
6. 重录；
7. 主动保存；
8. 麦克风权限被拒绝；
9. 录音失败；
10. 保存失败。

权限拒绝和录音失败状态应允许重试、返回声音来源选择，或改用本地导入。

### 3.4 本地导入状态

Figma 流程至少覆盖：

1. 选择本地音频入口；
2. 文件选择后的处理中状态；
3. 导入完成与试听；
4. 重新导入；
5. 主动保存；
6. 文件格式不支持或文件损坏；
7. 导入失败；
8. 保存失败。

失败状态应允许重新选择文件、返回声音来源选择或取消创建。

### 3.5 完成与角色切换

- 声音保存成功后，draft 才转为 active character；
- 创建完成后关闭临时操作层并返回场景；
- 场景入口显示当前角色头像和清晰但轻量的可切换提示；
- 角色切换层显示已有角色头像列表、名字和当前角色标识；
- 选择其他角色后关闭切换层并回到场景；
- 新增角色入口与切换入口在视觉和语义上保持区分。

## 4. 建议的核心流程

### 4.1 首次创建并录音

```text
首次创建入口
→ 名字与形象
→ 选择“现场录音”
→ 权限说明
→ 录音中
→ 停止
→ 试听
→ 保存
→ 创建完成并返回场景
```

### 4.2 新增角色并本地导入

```text
场景角色入口
→ 新增角色
→ 名字与形象
→ 选择“本地导入”
→ 选择文件
→ 导入完成
→ 试听
→ 保存
→ 创建完成并返回场景
```

### 4.3 切换已有角色

```text
场景当前角色头像
→ 头像列表
→ 选择已有角色
→ 当前角色标识更新
→ 返回场景
```

## 5. Figma 交付要求

本 Checkpoint 的 Figma 文件至少应包含：

- 一张主流程总览；
- 首次创建入口；
- 名字与形象选择；
- 录音 / 本地导入二选一；
- 录音中；
- 录音完成、试听、重录与保存；
- 导入完成、试听、重新导入与保存；
- 麦克风权限拒绝；
- 文件不支持；
- 保存失败；
- 已有角色头像列表；
- 当前角色切换入口；
- 桌面和移动端关键布局差异；
- 能够走通录音创建、导入创建和角色切换三条可点击路径。

线框应明确标记正常、进行中、成功、失败、不可用和确认状态，但不要求形成完整组件库。

## 6. 暂不纳入

本 Checkpoint 不制作：

- 完整视觉品牌系统；
- 全部页面高保真设计；
- 正式动画；
- 最终字体与色彩规范；
- 所有未来系统；
- 复杂游戏 HUD；
- 录音、导入或音频播放代码；
- 正式声音素材；
- 账号、多人、存档或内容管理界面。

## 7. 完成门槛

以下条件全部满足后，本 Checkpoint 才可标记为通过：

- 首次创建、再次新增和角色切换入口清楚且不会长期遮挡场景；
- 录音和本地导入两条路径均能从身份步骤走到保存并返回场景；
- 录音中、试听、重录、重新导入和保存状态均有明确操作；
- 麦克风权限拒绝、文件不支持和保存失败均有恢复路径；
- 未保存声音不能完成角色创建；
- 已有角色使用头像列表切换，并清楚标记当前角色；
- 桌面和移动端关键布局均可理解；
- 没有引入完整品牌系统、高保真全页面、复杂 HUD 或阶段 4 代码；
- 设计结果经项目方确认后，才进入阶段 4 实现。
