# Echo Cabin 核心声音交互 Web Prototype 范围

**文档版本：** V0.2  
**文档状态：** 已冻结，可进入实现  
**适用范围：** 当前公开可访问的核心声音交互 Web Prototype

## 1. 文档职责

本文件定义本轮 Web Prototype 的实际实现范围、测试参数、技术边界和验收标准。Project Charter 维护项目定位和 Demo 范围，Game Bible 维护稳定玩法规则，UX Flow 维护玩家流程和界面状态；当上游稳定规则发生变化时，应同步修改上游文档，而不是长期保留互相冲突的事实来源。

本轮实现、测试和验收以本文件中的 Prototype 参数为准，但不得用本文件覆盖上游产品规则。Web、GitHub Pages、虚拟坐标、具体音频增益和浏览器兼容要求只属于本轮验证载体，不代表正式 Demo 的最终技术方案。

## 2. 本轮目标

本轮验证以下核心体验：

1. 玩家创建最多 4 个代表具体人物的角色，并选择一个作为当前控制角色；
2. 当前控制角色通过点击或触摸目标位置在一个固定房间中移动；
3. 当前控制角色既是移动主体和聆听位置，也是可听见的本地自声来源；
4. 其他角色的声音根据与当前控制角色的距离连续、非线性衰减；
5. 多个角色使用彼此独立的间歇播放周期，并可同时被听见；
6. 玩家进入一个固定回忆物品的交互范围后，可以主动点击并听完整段语音；
7. 回忆物品播放期间，全部角色声音平滑退到背景，结束后平滑恢复；
8. 原型可通过公开链接访问，并在目标桌面和移动浏览器中验证。

本轮不是完整游戏，不验证正式账号、多人实时同步、完整布置流程、最终美术风格或正式技术架构。

## 3. Web Prototype 技术定位

本轮使用静态 Web 应用和 GitHub Pages，是为了降低测试者进入成本并快速验证核心声音空间体验。该 Web Prototype 是一次性验证壳，不代表正式 Demo 或最终产品的技术底座。验证结束后，再根据信号体验、移动端兼容性、音频稳定性和后续成本决定正式 Demo 继续使用 Web，还是回到 Godot。

本轮不为未来正式 Web 产品搭建账号、后端、数据库、多人同步、CMS 或大量未验证功能的技术预留。基础实现仍需合理分离场景与坐标、移动、角色状态与切换、音频、回忆物品、资源配置及页面恢复状态。

## 4. 纳入功能

### 4.1 固定场景与虚拟世界坐标

- 使用一个固定的室内房间和当前 `1920 × 1080` 场景资产；
- 场景采用固定的 `1920 × 1080` 虚拟世界坐标；
- 视觉画布根据浏览器可用区域等比缩放，不拉伸；
- 玩家、其他角色、移动目标、移动边界、物品、交互范围和声音距离均使用虚拟世界坐标；
- 本文件中的距离单位均指虚拟世界单位，不是浏览器 CSS 像素；
- 点击或触摸坐标需扣除画布偏移与留白，再按缩放比例转换；
- 画布留白区域不能成为移动目标；
- 房间合法移动区域固定，不切换场景；
- 移动端优先横屏，竖屏可显示轻量“请横屏体验”提示。

实现参考：

```text
worldX = (pointerX - canvasOffsetX) / canvasScale
worldY = (pointerY - canvasOffsetY) / canvasScale
```

实际实现必须以画布有效显示区域为基准处理偏移和缩放。

### 4.2 角色创建、位置与切换

- Demo 最多支持 4 个角色；
- 每个角色代表一个具体人物，并包含名字、预设形象和一段当前生效声音；
- 同一操作者可以代为创建多个角色；
- 创建角色时必须现场录制或从本地设备导入音频；
- 角色声音需经过试听并由玩家主动保存，保存成功后才完成角色创建；
- 角色必须具有声音，不允许创建无声角色；
- 第一轮核心测试至少覆盖 3 个角色，建议同时验证 4 个角色的高密度情况；
- 新角色创建后，从预设合法出生位置中分配一个未占用位置；
- 出生位置仅用于首次进入，角色之后可移动；
- 玩家可以从已有角色中选择任意一个作为当前控制角色；
- 非当前角色保持最后位置，不自主移动。

切换当前控制角色时：

1. 原当前角色停止接收移动输入并保留位置；
2. 原当前角色转为普通距离声源；
3. 新角色成为移动主体；
4. 镜头与聆听位置切换至新角色；
5. 新角色开始使用本地自声规则；
6. 系统重新计算全部角色声音。

角色创建、现场录制、本地音频导入、试听和保存均属于本轮范围。该规则不得擅自收缩为仅创建预配置角色，也不得允许跳过声音创建无声角色。

角色声音流程：

1. 玩家完成名字与预设形象设置；
2. 玩家选择现场录制或从本地设备导入音频；
3. 只有玩家主动选择现场录制时，系统才请求麦克风权限；
4. 录制或导入完成后进入试听；
5. 玩家可以重录、重新导入或替换当前临时声音；
6. 玩家主动保存后，声音成为该角色当前生效声音并完成创建；
7. 保存失败时保留在声音步骤并提供重试，不创建无声角色。

### 4.3 点击或触摸目标移动

- 点击或触摸合法房间位置设置移动目标；
- 当前控制角色自动向目标移动，到达后停止；
- 移动途中点击或触摸新的合法位置可更新目标；
- 玩家不能移动出合法移动区域；
- 点击角色、物品或 UI 时，对象交互优先，不同时触发场景移动；
- 核心流程同时支持鼠标和触摸，不依赖 `hover`；
- 场景交互区域设置 `touch-action: none`；
- 页面设置 `overscroll-behavior: none`；
- 页面滚动、双击缩放和回弹不得干扰核心操作；
- 本轮不使用虚拟摇杆；
- WASD 只可作为开发调试输入，不能作为验收依赖。

### 4.4 当前控制角色自声

- 当前控制角色必须能够听见自己的声音；
- 自声默认参与正常探索；
- 自声不随距离变化，也不按零距离计算为永久最大音量；
- 自声使用固定、受控且集中配置的本地基础增益；
- 第一版基础增益为 `0.20`，属于 Prototype 初始调试值；
- 本轮不提供面向玩家的自声音量滑杆或关闭开关，也不允许自声被完全关闭；
- 自声采用与其他角色相同的间歇播放周期；
- 回忆物品播放时，自声降至其目标增益的 `0.22`，播放结束后平滑恢复。

### 4.5 角色声音播放周期

所有角色声音统一采用：

> 播放一段声音  
> → 随机静默 1—3 秒  
> → 再次播放

- 每个角色的首次开始时间可加入轻微随机偏移；
- 每个角色的周期与每次静默时长彼此独立；
- 不使用无缝连续循环；
- 其他角色超出最大听觉距离后可以暂停后续周期，再次进入时开启新周期；
- 回忆物品播放期间，角色周期可以继续，但最终输出增益乘以 `0.22`；
- 不因物品播放而销毁、重建或整体重新启动角色音频节点。

### 4.6 其他角色的距离声音

第一版参数的权威定义如下：

| 参数 | 数值 |
| --- | ---: |
| 最大听觉距离 | 420 虚拟世界单位 |
| 完全清晰距离 | 80 虚拟世界单位 |
| 其他角色单角色最大增益 | 0.45 |
| 当前控制角色自声基础增益 | 0.20 |
| 回忆物品播放时角色增益比例 | 0.22 |
| 增益平滑时间 | 250–400 ms |

其他角色第一版使用 smoothstep 衰减：

```text
t = clamp(
  (distance - clearDistance)
  / (maxHearingDistance - clearDistance),
  0,
  1
)

smoothstep = t² × (3 - 2t)
attenuation = 1 - smoothstep
targetGain = maxGain × attenuation
```

- 距离小于或等于 80 时，其他角色目标增益为 `0.45`；
- 距离处于 80 到 420 之间时，按公式连续、非线性衰减；
- 距离大于或等于 420 时，目标增益为 `0`；
- 当前角色自声不使用该距离公式；
- 所有增益变化均使用 Web Audio API 的平滑参数变化；
- 公式和数值可在 Playtest 后调整，但实现者不得在文档更新前自行替换。

### 4.7 音频结构与输出余量

- 每个角色拥有独立 gain；
- 当前角色自声与其他角色进入 Character Bus；
- 回忆物品语音进入独立 Memory Bus；
- Character Bus 与 Memory Bus 最后进入 Master；
- 第一版不使用 compressor，也不依赖 compressor 修复错误的基础增益。

| 参数 | 初始值 |
| --- | ---: |
| Character Bus gain | 0.40–0.50，按素材验收 |
| Memory Bus gain | 0.70，按素材验收 |
| Master gain | 1.0，必要时按整体输出调整 |

当前角色自声与最多 3 个其他角色同时处于各自最大目标增益时，Character Bus 的理论输出峰值应控制在约 `0.5` 以下。实际验收必须覆盖至少 3 个角色，并建议覆盖 4 个角色最密集情况；所有素材需无削波、破音、明显过载，且不同角色仍可分辨。

### 4.8 固定回忆物品交互

第一版使用一个预设回忆物品。其视觉、声音、坐标和交互锚点通过配置接入，后续可替换。本轮不实现新增、移动、删除或摆放。

| 参数 | 数值 |
| --- | ---: |
| 进入交互范围 | ≤ 150 虚拟世界单位 |
| 离开交互范围 | > 165 虚拟世界单位 |
| 玩家距离锚点 | 当前角色脚底中心 |
| 物品距离锚点 | 物品底部中心或配置锚点 |

交互规则：

1. 距离小于或等于 150 时进入可交互状态并显示提示；
2. 150 到 165 之间保持上一范围状态，避免提示闪烁；
3. 距离大于 165 时退出可交互状态并隐藏提示；
4. 进入范围不会自动播放；
5. 只有处于可交互状态且点击或触摸命中物品区域时，才从头播放；
6. 播放开始后，即使玩家离开范围，也自然播放至结束；
7. 离开范围只取消提示，不影响已经开始的声音；
8. 播放期间不能重复触发，也不能由另一物品抢占；
9. 播放结束后，必须重新满足范围与主动点击条件才能再次播放；
10. 不保留上次播放进度。

### 4.9 音频优先级

- 物品语音开始时，全部角色声音在 250–400 ms 内平滑降低至各自当前目标增益的 `0.22`；
- 播放期间，其他角色继续按距离计算，自声保持固定基准，再统一乘以 `0.22`；
- 物品自然结束后，全部角色声音在 250–400 ms 内恢复到届时状态对应的目标增益；
- 第一版物品语音不根据距离改变音量。

### 4.10 音频初始化与恢复

- 页面加载时不得自动创建并播放角色音频；
- 音频初始化必须绑定到用户第一次明确点击或触摸“开始体验”；
- 初始化时检查并处理 `AudioContext` 的 `suspended` 状态；
- 页面从后台返回后，如音频被浏览器挂起，显示可点击或触摸的恢复入口；
- 不绕过浏览器自动播放限制；
- 本轮不承诺锁屏或后台持续播放。

## 5. 资源配置边界

视觉和音频资源不得硬编码进交互逻辑，应通过集中配置或可替换资源路径接入。配置至少覆盖：

- 场景资源与合法移动区域；
- 角色 ID、名字、形象、声音、初始坐标与出生位置；
- 初始当前控制角色；
- 回忆物品资源、坐标和交互锚点；
- 自声、距离、总线与淡入淡出参数；
- 移动速度。

Codex 不负责生成最终美术、最终角色设计、最终物品设计或替换项目方声音，也不从互联网下载临时音频。项目方负责确认资源内容、基础质量和公开使用权限。

角色创建期间由玩家现场录制或从本地设备导入的音频属于用户提供内容，不属于 Codex 下载或替换的临时素材。Web 实现必须处理麦克风授权、拒绝授权、录制失败、文件导入失败、试听和保存失败状态。

## 10. 验收标准

以下条件全部满足后，本轮 Prototype 才可通过：

1. 页面加载不自动播放声音；
2. 用户明确点击或触摸“开始体验”后才初始化 AudioContext；
3. 当前控制角色开始播放自己的间歇声音，且玩家可听见自声；
4. 自声不按零距离变成最大音量，初始目标增益为 `0.20`；
5. 玩家可通过鼠标或触摸设置和更新合法移动目标；
6. 页面滚动、回弹和缩放不干扰场景操作；
7. 点击角色、物品或 UI 不误触发场景移动；
8. 玩家创建角色时可以选择现场录制或从本地设备导入音频；
9. 麦克风权限只在玩家主动选择录制时请求，拒绝后可重试或改用导入；
10. 录制或导入后可以试听、重录或重新导入，只有主动保存后才完成角色创建；
11. 保存、录制或导入失败时提供明确反馈，不创建无声角色；
12. 玩家可创建并在最多 4 个角色间切换当前控制角色；
13. 切换后位置、聆听身份、自声身份和其他角色距离声音正确重算；
14. 全部角色均使用播放后随机静默 1—3 秒的独立周期；
15. 其他角色距离小于或等于 80 时目标增益为 `0.45`；
16. 其他角色距离大于或等于 420 时目标增益为 `0`；
17. 80 到 420 之间按 smoothstep 连续、非线性衰减；
18. 所有距离基于 `1920 × 1080` 虚拟世界坐标；
19. 不同浏览器尺寸下，同一虚拟距离产生一致结果；
20. 至少 3 个角色、建议 4 个角色同时播放时，无削波、破音或明显过载；
21. Character Bus 理论输出峰值控制在约 `0.5` 以下；
22. 玩家进入物品范围后看到提示，但不会自动播放；
23. 进入阈值为 150，离开阈值为 165，并正确使用迟滞；
24. 只有范围内主动点击或触摸命中物品才开始播放；
25. 播放开始后离开范围不造成中断；
26. 播放期间不能重复触发或被另一物品抢占；
27. 物品播放期间，全部角色声音降至各自目标增益的 `0.22`；
28. 物品自然结束后，角色恢复到届时状态对应的目标增益；
