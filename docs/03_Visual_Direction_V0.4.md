# 《回声小屋》视觉方案总结 V0.4

**项目名称：**《回声小屋》 / Echo Cabin  
**当前阶段：** 美术探索收束 / Character Lock / Scene Alignment  
**文档状态：** 角色基础画风与主镜头方向已确认；场景绘制规则基本收束；色彩脚本、实际角色尺寸及场景资产表现仍需校准测试。

## 1. 视觉目标

《回声小屋》的视觉设计服务于“朋友声音进入空间并产生关系”的核心体验。画面首先要让玩家清楚看到具体人物、彼此距离、靠近与聚集，其次才承担环境氛围和空间装饰。

当前视觉方案不追求高精度写实、复杂装修或大型探索世界，而是建立一套清爽、温暖、易于开发，并能够扩展到室内外多个声音空间的统一美术语言。

Demo 最多支持四个代表具体人物的角色，需要在同一小型空间内表现单人聆听、多人声音重叠和相对安静的边缘体验。因此视觉设计必须优先保证角色辨识度、群体聚集可读性和移动区域清晰度。

## 2. 整体视觉定义

《回声小屋》的整体美术方向定义为：

> **清爽治愈系 Q 版手绘动画风。**

英文内部描述可使用：

> **Clean Cozy Chibi Animation Style**

其核心特征包括：

- 清爽、温暖、亲近；
- Q 版但不过度幼儿化；
- 简化圆润的形体；
- 清晰而柔和的彩色描边；
- 平涂为主，搭配少量柔和体积阴影；
- 轻微手绘感，但不采用厚重笔触；
- 角色具有较强情感投射能力；
- 场景安静、有氛围，但视觉权重低于角色；
- 适用于室内小屋及未来庭院、海边、教室、车站等独立声音空间。

整体统一性主要依靠镜头、形体、描边、上色方式、光影结构和细节密度建立，**不依赖所有场景使用同一套固定颜色**。

## 3. 镜头与空间规则

### 3.1 主镜头

当前主镜头确定为：

> **横屏、固定正面、浅纵深的 2.5D 社交空间镜头。**

具体规则：

- 后墙基本正对镜头；
- 仅保留轻微俯视，以看见一定地面深度；
- 场景横向宽、纵向浅；
- 不使用明显高俯视；
- 不使用严格等距视角；
- 不使用纯横版单线侧视；
- 不使用自由旋转镜头；
- 不使用复杂楼梯、多层地形或深走廊。

### 3.2 移动空间

角色可以：

- 左右自由移动；
- 在浅纵深范围内进行少量前后移动；
- 形成三角形、弧形或松散团簇；
- 实现三人聚集、一人稍远，或两两聚集等关系状态。

浅纵深并不要求画面显示明确轨道。系统内部仍使用二维世界坐标计算角色距离，声音随距离连续变化。

### 3.3 镜头待验证项

当前视觉方向更倾向固定全景，但仍需在 Prototype 中验证：

- 固定镜头能否完整容纳四个角色和小型场景；
- 是否需要非常有限的镜头平移；
- 角色切换时是否只切换控制与聆听位置，而不移动镜头。

验证完成后，再决定是否同步修改 Game Bible，当前视觉文档不直接覆盖上游玩法规则。

## 4. 角色美术规则

### 4.1 角色基础定义

角色采用：

> **清爽、温暖、轻日系动画感的 Q 版手绘人物。**

角色不是 NPC 模板或普通装饰公仔，而是具体朋友声音与身份的视觉载体。

### 4.2 比例与结构

- 约 2.5—3 头身；
- 头部视觉占比较高；
- 身体短小、肩部较窄；
- 四肢简化但结构完整；
- 小手和小脚清楚可见；
- 站姿稳定；
- 不使用写实人体比例；
- 不使用豆子、软糖或无头身区分的一体角色；
- 不使用极端婴儿式大头比例。

即使只看纯色剪影，也应能够辨认头部、躯干、手臂、双腿及角色朝向。

### 4.3 五官与情绪

- 眼睛偏圆；
- 瞳孔视觉占比较大；
- 眼神柔和、明亮；
- 鼻子弱化；
- 嘴型小而克制；
- 默认表情为自然轻微微笑；
- 保留柔和腮红；
- 不使用夸张闪亮动漫眼；
- 不使用无神黑点式五官；
- 不使用持续卖萌、搞怪或夸张兴奋表情。

角色应传达：

- 友善；
- 温暖；
- 安静；
- 可信任；
- 有陪伴感；
- 适合承载真实朋友声音。

### 4.4 发型

- 轻微蓬松；
- 带少量自然微乱感；
- 使用大块发束；
- 发梢形成清楚剪影；
- 不依赖大量细碎发丝；
- 正面、侧面、背面体积保持一致。

未来不同角色可以通过发长、刘海、发尾方向、顶部轮廓、发色和少量发饰形成差异，但不得破坏统一的体积、描边和细节密度。

### 4.5 服装

基础母版使用简单日常服装：

- 简单上衣；
- 简单短裤或基础下装；
- 不使用复杂图案；
- 不绑定卧室、职业或场景身份；
- 不将睡衣、制服或主题服装作为默认形象。

未来个性化优先通过发型、发色、肤色、服装颜色和少量配饰完成。当前 Demo 不开发复杂换装系统，AI 角色生成也不属于当前 Demo 范围。

### 4.6 描边与上色

描边规则：

- 不使用纯黑；
- 使用深灰蓝、灰紫、暖灰棕等柔和彩色描边；
- 外轮廓最清楚；
- 头发内部结构线次之；
- 服装和身体内部线更轻；
- 面部细节最克制；
- 描边有轻微粗细变化，但不过度漫画化。

上色规则：

- 平涂为主；
- 少量柔和体积阴影；
- 不使用写实皮肤光泽；
- 不使用重厚涂；
- 不使用复杂服装和材质纹理；
- 不采用强烈硬边赛璐璐阴影。

### 4.7 多视角与基础状态

角色母版至少需要：

1. 正面；
2. 四分之三正面；
3. 侧面；
4. 四分之三背面；
5. 背面。

Demo 初期只制作：

- 待机；
- 行走；
- 发声；
- 当前控制状态。

暂不制作跑步、跳跃、坐姿、复杂表情和大量情绪动画。

### 4.8 游戏内角色尺寸

当前建议：

- 角色高度约占游戏画面高度的 15%—18%；
- 同屏最多四个角色；
- 多人聚集时不能完全重叠；
- 后排角色至少保留头部和主要身体轮廓；
- 角色视觉权重高于普通环境装饰和回忆物品。

该比例仍需放入实际 844:390 游戏画面中做最终校准。

## 5. 场景美术规则

### 5.1 场景定位

当前 Demo 场景不是传统卧室装修模板，也不是大型探索地图，而是：

> **一个能承载移动、靠近、声音重叠和回忆物品的独立声音空间。**

Demo 当前只制作一个小型室内场景。未来可扩展多个室内外场景，但当前不开发场景选择、地图和解锁系统。

### 5.2 场景与角色关系

场景必须向已经确认的角色风格靠拢：

- 场景比角色更简；
- 场景描边比角色更轻；
- 场景阴影复杂度不高于角色；
- 角色始终是第一视觉重点；
- 建筑和窗景不得压过角色；
- 角色放入场景后不能像贴纸，也不能被背景吞没。

### 5.3 形体语言

场景采用：

- 简化、圆润的大形体；
- 略带手绘不规则；
- 清楚但柔和的建筑轮廓；
- 大色块优先；
- 低细节密度；
- 每个场景保留 1—2 个主要建筑记忆点。

适合使用：

- 圆角窗或大开口；
- 弧形门洞；
- 浅壁龛；
- 内嵌平台；
- 柔和墙面转角；
- 少量结构色块。

避免：

- 大量重复框架；
- 过多墙面分割线；
- 硬朗科技舱结构；
- 复杂写实透视；
- 模型盒或微缩玩具屋效果。

### 5.4 描边层级

- 角色外轮廓最清楚；
- 窗、门和主要建筑边界使用中等强度描边；
- 墙面、地面和内部结构线更轻；
- 不给每个色块都单独勾边；
- 不使用纯黑粗建筑线；
- 场景描边主要帮助空间阅读，不承担漫画表现。

### 5.5 材质与细节

场景使用：

- 平涂为主；
- 少量柔和体积阴影；
- 轻微手绘表面纹理；
- 简化、非写实的材质表达；
- 清楚的资产轮廓。

不再采用：

- 深棕木屋；
- 乡村农场风；
- 大量写实木纹；
- 真实软陶模型；
- 真实纸雕舞台；
- 高完成度厚涂概念插画；
- 复杂微缩摄影材质。

纸感和软陶感可作为少量辅助语言：

- 纸感用于轻微纹理、边缘和部分 UI；
- 软陶感用于角色或物品的圆润体积；
- 不将整个世界制作成真实纸雕或软陶模型。

## 6. 空场景美感

场景初始为空，玩家后续逐步加入回忆物品。因此场景不能依赖家具和摆件填满之后才好看。

空状态美感主要来自：

- 镜头构图；
- 建筑轮廓；
- 主开口或窗景；
- 光影节奏；
- 色块关系；
- 空间层次；
- 角色在空间中的位置关系。

每个空场景可保留：

- 一个主要建筑特征；
- 一个次级结构；
- 少量固定环境细节；
- 大面积连续活动区域。

不得通过以下方式解决空旷：

- 固定床、柜子和家具套装；
- 大量植物；
- 满墙挂画；
- 多件固定回忆物品；
- 复杂地毯和装饰；
- 大量没有互动意义的小道具。

理想体验是：

- 空场景已经成立，愿意停留；
- 放入一两件回忆物品后开始出现个人痕迹；
- 放入三四件物品后形成“属于我们”的空间；
- 玩家物品增强场景，而不是拯救一个难看的空壳。

## 7. 色彩与氛围规则

### 7.1 不冻结统一色盘

《回声小屋》不为所有场景冻结统一的固定主色和阴影色。

灰蓝、灰紫、灰绿等只属于可选方案，不是默认答案。若统一使用灰色低饱和色盘，可能削弱不同场景的情绪和记忆感。

### 7.2 场景独立色彩脚本

每个场景可以根据以下因素建立独立 Color Script：

- 地点；
- 时间；
- 天气；
- 关系语义；
- 回忆情绪；
- 场景声音氛围。

允许变化：

- 主色相；
- 冷暖关系；
- 饱和度；
- 光色；
- 阴影色；
- 环境色；
- 局部高亮色。

例如：

- 小屋可使用暖杏、珊瑚、浅金及蓝绿色对比；
- 花园可使用黄绿日光、青绿阴影和花朵跳色；
- 海边可使用高明度青蓝、亮黄光线和紫红阴影；
- 教室可使用苍白日光、青色墙面和橙红局部；
- 车站可使用橘红夕阳、深蓝阴影和黄色灯光。

### 7.3 色彩统一原则

虽然场景颜色可以明显变化，但必须保持：

- 角色与背景有明确明度或色相分离；
- 大色块优先；
- 光区与影区清楚；
- 高饱和颜色集中使用；
- 背景不得比角色更抢眼；
- 不使用黑色或脏棕作为所有场景的默认阴影；
- 不使用统一灰蓝或灰紫强行维持项目一致性；
- 不使用无控制的糖果色和彩虹色堆叠。

视觉统一主要由镜头、形体、描边、上色、光影结构和细节密度建立；色彩负责场景身份与氛围变化。

## 8. 回忆物品美术规则

Demo 支持 2—4 件可绑定声音的回忆物品。回忆物品不是装修收藏系统中的普通家具，而是完整声音记忆的视觉入口。

物品规则：

- 清楚轮廓；
- 一个主要识别特征；
- 低细节；
- 柔和彩色描边；
- 平涂加少量阴影；
- 材质复杂度低于或等于角色；
- 缩小后仍能辨认；
- 点击区域容易理解；
- 不依赖细小文字、按钮和纹理。

例如收音机保留：

- 主体轮廓；
- 扬声器；
- 一个旋钮；
- 一根天线。

不需要复杂刻度、多按钮、精细木纹和金属反光。

物品摆放的格点、锚点和合法位置属于 Object Placement Spec，不应永久绘制在场景概念图中。

## 9. UI 方向

UI 延续角色和场景的绘制语法：

- 柔和圆角；
- 彩色灰描边；
- 浅色卡片；
- 简化图标；
- 低至中等饱和状态色；
- 少量手绘不规则；
- 清楚但不厚重。

避免：

- 深色硬边游戏 HUD；
- 木质拟物面板；
- 糖果色儿童按钮；
- 大量常驻菜单；
- UI 覆盖角色和声音空间；
- 装修游戏式重型物品栏。

UI 只服务当前角色、录音、切换、物品管理和必要反馈，不成为场景视觉主角。

## 10. 声音视觉反馈

声音距离仍由系统后台计算，正常探索状态不长期显示调试式声波范围。

发声可使用：

- 轻微身体起伏；
- 头部小幅动作；
- 嘴部极简变化；
- 一至两圈短暂、极淡的柔和脉冲；
- 角色轮廓或名字短暂高亮。

当前控制角色可使用：

- 轻描边高亮；
- 脚底柔和小环；
- 极弱光晕；
- 名字状态变化。

不使用：

- 永久声波圈；
- 大面积距离半径；
- 调试网格；
- 过强发光；
- 遮挡角色本体的特效。

## 11. 多场景扩展原则

未来不同声音空间可以在题材、色彩和氛围上明显变化，但必须统一：

- 正面浅纵深镜头；
- 角色比例；
- 形体简化程度；
- 描边层级；
- 上色方式；
- 阴影复杂度；
- 资产细节密度；
- 角色高于背景的视觉优先级。

未来场景可以包括：

- 小屋；
- 花园；
- 海边平台；
- 教室；
- 校园角落；
- 街边小广场；
- 车站；
- 屋顶或露台。

当前不将其扩展为复杂开放世界。每个场景仍是一个独立、可停留、可聚集和可承载声音记忆的空间。

## 12. 当前明确排除的方向

- 高角度俯视；
- 严格等距装修视角；
- 纯横版单线移动；
- 深棕木屋和乡村农场风；
- 真实软陶模型；
- 纯纸雕剧场；
- 高完成度厚涂概念插画；
- 儿童电视动画式粗黑描边；
- 豆子、软糖或无四肢角色；
- 完整实时 3D 角色；
- 依靠家具堆叠才成立的场景；
- 永久可见的格点、锚点和声波圈；
- 复杂装修、经营和家具收集系统。

## 13. 当前已确认与待验证内容

### 已确认

- 角色基础画风；
- 角色比例和身体结构；
- 五官与发型语言；
- 角色描边与上色方向；
- 五视图资产需求；
- 主镜头方向；
- 场景需要向角色画法靠拢；
- 空场景不能依赖家具堆叠；
- 色彩采用场景独立脚本，不锁统一色盘；
- 场景未来可扩展至室外声音空间。

### 待验证

- 游戏内角色最终尺寸；
- 四角色聚集时的遮挡；
- 浅纵深移动手感；
- 固定镜头与 Game Bible 镜头跟随规则的冲突；
- 场景描边最终强度；
- 场景阴影最终强度；
- 空状态与轻摆放状态的完成感差异；
- 室内外场景在不同色彩脚本下的一致性；
- 发声、当前控制和物品播放状态的视觉反馈。

## 14. 当前 Checkpoint
