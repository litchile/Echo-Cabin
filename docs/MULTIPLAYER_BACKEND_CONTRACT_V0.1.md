# 3D 球形声音世界多人后端合同 V0.1

**工作名称：** 待定  
**文档版本：** V0.1  
**日期：** 2026-07-26  
**上游规则：** `CORE_LOOP_V0.2.md`  
**状态：** 已完成内部技术边界审批，尚未选定云服务与正式部署方案  

## 1. 目标

本合同把产品循环转换为可以实现和测试的服务端边界，覆盖：

- 账号与一人一角色；
- 邀请制四人星球；
- 球面移动与实时位置同步；
- 短音频资源与距离声音元数据；
- 有效相遇、双方回应和关系共鸣；
- 轻量种植与回声碎片账本；
- 物品购买、摆放、声音绑定和赠送；
- 权限、幂等、防复制与基础安全。

本合同不选择美术资产、角色外观、星球材质、物品造型或正式 UI。

## 2. 架构原则

1. **服务器权威：** 位置合法性、相遇、关系、碎片、作物、物品和赠送最终由服务器确认。
2. **客户端预测：** 本机移动保持即时，服务器快照用于纠正，不让网络延迟直接破坏移动手感。
3. **事件幂等：** 任何可能被客户端重试的写操作都必须携带幂等键。
4. **关系无序：** 两名玩家的关系使用规范化无序玩家对，不能产生 A-B 与 B-A 两份数据。
5. **声音最小暴露：** 客户端只获得当前有权访问的短期声音地址，不暴露永久存储路径。
6. **音频客户端混合：** 服务端同步位置和声音引用，距离衰减与最终混音在每台设备本地完成。
7. **参数可配置：** 相遇距离、停留时间、成熟时间、价格和容量不写死在业务代码。
8. **先单体后拆分：** V0.1 可以使用模块化单体和一个实时网关，不为未来规模提前拆微服务。

## 4. 身份与星球

### 4.1 身份

- 所有写请求必须带有有效用户会话；
- 一个用户只能拥有一个当前正式角色；
- 角色声音和物品声音都必须记录声音所有者；
- 被封禁或退出星球的用户不能继续通过旧连接写入状态。

### 4.2 星球成员

- 一个星球最多 4 名正式成员；
- 邀请必须包含创建者、接收者、星球、过期时间和状态；
- 接收者明确接受后才创建成员关系；
- 重复接受同一邀请不能创建重复成员；
- V0.1 一个用户只能拥有一个主要星球成员关系；
- 离开星球是高风险操作，必须在后续 UI 中二次确认。

### 4.3 权限角色

| 行为 | 普通成员 | 星球创建者 |
| --- | ---: | ---: |
| 移动自己的角色 | 是 | 是 |
| 修改自己的角色声音 | 是 | 是 |
| 编辑自己的菜地与物品 | 是 | 是 |
| 聆听有权访问的成员声音 | 是 | 是 |
| 邀请新成员 | 否 | 是 |
| 移除违规公开内容 | 否 | 是 |
| 编辑他人物品或声音 | 否 | 否 |

创建者的管理权不等于其他玩家内容的所有权。

## 5. 球面实时位置

### 5.1 坐标格式

角色位置使用归一化球面方向：

```ts
type SurfaceDirection = {
  x: number
  y: number
  z: number
}
```

约束：

- `x² + y² + z²` 必须接近 1；
- 服务端保存前重新归一化；
- 球面距离使用 `radius * acos(clamp(dot(a, b), -1, 1))`；
- 物品位置额外保存表面高度和绕法线朝向。

### 5.2 点击移动协议

客户端不持续上传任意位置，而是发送球面目标：

```json
{
  "type": "move.target",
  "clientSequence": 1042,
  "targetDirection": { "x": 0.21, "y": 0.37, "z": 0.90 }
}
```

服务器：

1. 校验目标为有限数值并重新归一化；
2. 校验目标位于当前星球合法表面；
3. 按配置速度沿大圆路径推进角色；
4. 定期广播权威位置快照；
5. 到达目标、收到新目标、断线或进入禁止移动模式时停止。

### 5.3 同步频率

- 服务器内部移动模拟目标：10—20 Hz；
- 权威位置广播目标：10 Hz；
- 客户端使用插值渲染远端角色；
- 本地角色使用预测，超过容差时柔和纠正；
- 不要求每个渲染帧发送网络数据。

具体频率必须通过网络测试确定，以上为首版预算而非永久常量。

### 5.4 重连

- 实时连接持有短期房间会话标识；
- 断线进入短宽限状态，角色停止移动并保留最后权威位置；
- 宽限期内重连恢复同一 Presence；
- 超时后广播离线并结束未完成的相遇累计；
- 旧连接恢复后不能覆盖新连接状态。

## 6. 声音合同

### 6.1 V0.1 声音类型

- `character_clip`：角色当前生效的短声音；
- `item_clip`：绑定到物品的完整声音记忆。

首版继续使用预先录制或导入的短音频，不实现实时语音通话、语音房或服务端音频转发。

### 6.2 上传流程

```text
客户端请求上传授权
→ 服务端创建 pending SoundAsset
→ 客户端直传对象存储
→ 客户端提交上传完成
→ 服务端校验格式、时长、大小和所有者
→ 安全处理完成
→ SoundAsset 变为 ready
→ 玩家主动保存后原子替换正式声音引用
```

上传失败、处理失败或保存失败都不能提前删除原声音引用。

### 6.3 访问控制

- 声音默认只对同星球有效成员开放；
- 客户端通过短期签名地址或授权代理读取；
- 退出星球或被移除后，不再签发新访问地址；
- 日志中不记录原始音频内容；
- 删除操作先撤销引用，再进入可恢复的延迟物理删除队列；
- 赠送普通物品时不转移已绑定声音。

## 7. 相遇与双方回应

### 7.1 相遇状态机

```text
outside
→ candidate
→ qualified
→ response_available
→ responded | ended
```

- `candidate`：双方进入相遇范围；
- `qualified`：累计满足停留和近期活动条件；
- `response_available`：允许任一方发起一次回应；
- `responded`：另一方接受，本周期关系共鸣已确认；
- `ended`：离开范围、离线或超时。

### 7.2 服务器判定

- 相遇依赖服务端权威位置，不接受客户端直接上报“已相遇”；
- 20 秒累计、3 秒离开宽限和60秒近期活动均为配置；
- 同一玩家对同一时间只允许一个活动相遇；
- 同一玩家对每24小时最多产生一次共鸣增加；
- 未接受的回应在离开或超时后过期；
- 拒绝不扣除资源，不广播给其他成员。

### 7.3 关系键

关系主键使用排序后的玩家标识：

```text
relationship_key = min(user_a, user_b) + ":" + max(user_a, user_b)
```

增加共鸣时必须锁定或原子更新同一关系记录，并使用相遇回应幂等键防止重复。

## 8. 种植与回声碎片

### 8.1 作物时间

- 服务端保存 `plantedAt` 和由规则计算的 `maturesAt`；
- 成熟是时间派生状态，不依赖后台定时任务逐株修改；
- 查询或操作时根据服务端当前时间计算是否成熟；
- 朋友浇水产生有限的 `growthReductionSeconds`；
- 总加速不能超过该作物配置上限。

### 8.2 作物状态机

```text
empty
→ growing
→ mature
→ harvested
→ exchanged | inventory_crop | gift_pending
```

同一作物实例只能成功收获一次。收获、创建收获物和返还种子必须在同一事务中完成。

### 8.3 碎片账本

账本不只保存余额，必须保存每一次变化：

```ts
type FragmentEntry = {
  id: string
  userId: string
  delta: number
  reason: 'crop_exchange' | 'item_purchase' | 'admin_adjustment'
  referenceId: string
  idempotencyKey: string
  createdAt: string
}
```

- `userId + idempotencyKey` 唯一；
- 余额不能在购买事务后小于 0；
- 首版不提供用户间碎片转账；
- 管理调整必须记录操作者和原因；
- 客户端展示余额可以缓存，但写入只认服务端账本。

## 9. 物品、摆放与赠送

### 9.1 购买

购买事务必须同时：

1. 校验目录物品可用和价格版本；
2. 校验碎片余额；
3. 写入负数账本记录；
4. 创建唯一物品实例；
5. 返回新余额和物品。

任何一步失败则全部回滚。

### 9.2 球面摆放

- 客户端发送物品、球面方向、表面高度和朝向；
- 服务端校验物品所有者、状态、星球成员、容量和占用；
- 成功后创建或更新唯一 Placement；
- 物品处于 `placed` 时不能同时赠送；
- 收回后删除 Placement 并将物品改回 `inventory`；
- 服务器不信任客户端对“合法位置”的判断。

### 9.3 赠送事务

- 可赠送对象：未绑定声音的背包普通物品或库存作物；
- 创建 Gift 时锁定对象为 `gift_pending`；
- 接受时在同一事务中转移所有权并结束 Gift；
- 拒绝或过期时在同一事务中解锁并归还赠送者；
- 同一对象同时只能关联一个活动 Gift；
- 客户端重试不能复制物品或作物。

## 10. 推荐接口边界

接口路径是语义合同，不代表已经选定 HTTP 框架。

### 10.1 HTTP 写接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `POST` | `/v1/planets` | 创建主要星球 |
| `POST` | `/v1/planets/{id}/invites` | 发起成员邀请 |
| `POST` | `/v1/invites/{id}/accept` | 接受邀请 |
| `PUT` | `/v1/character` | 更新本人角色基础信息 |
| `POST` | `/v1/sounds/uploads` | 创建声音上传授权 |
| `POST` | `/v1/sounds/{id}/commit` | 确认并处理上传 |
| `PUT` | `/v1/character/sound` | 原子替换角色声音 |
| `PUT` | `/v1/items/{id}/sound` | 原子替换物品声音 |
| `POST` | `/v1/encounters/{id}/responses` | 发起回应 |
| `POST` | `/v1/responses/{id}/accept` | 接受回应 |
| `POST` | `/v1/garden/plots/{slot}/plant` | 播种 |
| `POST` | `/v1/crops/{id}/water` | 浇水 |
| `POST` | `/v1/crops/{id}/harvest` | 收获 |
| `POST` | `/v1/crops/{id}/exchange` | 兑换碎片 |
| `POST` | `/v1/items/purchase` | 购买普通物品 |
| `POST` | `/v1/items/{id}/place` | 摆放或移动物品 |
| `POST` | `/v1/items/{id}/pick-up` | 收回物品 |
| `POST` | `/v1/gifts` | 发起赠送 |
| `POST` | `/v1/gifts/{id}/accept` | 接受赠送 |
| `POST` | `/v1/gifts/{id}/decline` | 拒绝赠送 |

所有 POST/PUT 写接口必须接收 `Idempotency-Key`。

### 10.2 HTTP 读模型

- `/v1/bootstrap`：当前用户、角色、主要星球和实时连接授权；
- `/v1/planets/{id}/state`：星球静态状态、成员、物品和菜地；
- `/v1/inventory`：物品、作物、种子和待处理赠送；
- `/v1/catalog`：物品与作物配置版本；
- `/v1/relationships`：星球内关系进度与已解锁能力；
- `/v1/sounds/{id}/access`：有权限时签发短期读取地址。

### 10.3 实时消息

客户端到服务器：

- `room.join`
- `move.target`
- `move.cancel`
- `presence.ping`

服务器到客户端：

- `room.snapshot`
- `player.joined`
- `player.left`
- `player.position`
- `encounter.qualified`
- `response.created`
- `response.accepted`
- `world.item_changed`
- `world.crop_changed`

经济、赠送和声音写操作继续走幂等 HTTP 事务；实时通道只推送结果，不承担账本写入。

## 11. 数据一致性

### 11.1 必须强一致的操作

- 回声碎片发放与扣除；
- 作物收获与兑换；
- 物品实例创建；
- 赠送所有权转移；
- 关系共鸣增加；
- 正式声音引用替换；
- 球面位置占用确认。

### 11.2 可以最终一致的内容

- 远端角色位置插值；
- 在线成员列表短暂状态；
- 观察指标和分析事件；
- 声音处理完成通知；
- 非关键展示缓存。

## 12. 隐私与安全底线

- 默认只服务受邀请熟人，不代表可以省略屏蔽、退出和举报能力；
- 声音文件不得使用可猜测的公开永久 URL；
- 上传内容必须限制格式、大小、时长和数量；
- 日志和分析事件不得包含声音正文或未脱敏签名地址；
- 删除账号需要处理角色声音、物品声音、关系与赠送中的所有权；
- 星球创建者无权下载其他成员的原始音频文件；
- 生产环境必须使用传输加密和服务端密钥管理；
- 分析数据与游戏状态数据分开保留。

## 13. 可观测性

后端至少记录：

- 实时连接成功率、重连率和位置纠正次数；
- 相遇候选、有效相遇、回应发起和回应接受；
- 作物播种、成熟、收获、兑换和朋友浇水；
- 碎片来源与支出分布；
- 物品购买、摆放、收回、声音绑定和聆听；
- 赠送发起、接受、拒绝、过期和失败；
- 音频上传、处理、保存和访问失败；
- 幂等冲突、权限拒绝和异常回滚。

观察指标不能成为面向玩家的任务进度或排行榜。

## 14. 实施顺序

### 阶段 A：本地服务合同验证

- 使用内存或本地数据库实现领域状态机；
- 两个模拟玩家连接同一星球；
- 验证球面移动、位置快照和相遇判定；
- 验证种植时间、碎片账本、购买和赠送幂等；
- 使用现有占位声音，不接正式存储。

### 阶段 B：持久化与对象存储

- 接入正式数据库迁移；
- 接入声音对象存储与短期访问授权；
- 实现断线重连和星球状态恢复；
- 加入权限、配额、删除和审计。

### 阶段 C：有限真实多人测试

- 邀请制测试账号；
- 小规模实时连接；
- 调整快照频率、位置容差、相遇时长与种植产出；
- 验证没有朋友在线时的个人节奏，以及朋友上线后的声音优先级。

正式美术、完整角色定制、物品造型生产和星球环境资产必须在用户把关后进入，不属于上述阶段的自动推进范围。

## 15. V0.1 技术验收

1. 两个客户端可以加入同一星球并看到插值后的远端位置；
2. 服务器能拒绝速度异常、非法球面方向和旧连接写入；
3. 客户端不能伪造有效相遇；
4. 双方回应重试不会重复增加关系共鸣；
5. 作物不会因客户端修改时间提前成熟；
6. 同一作物不能重复收获或兑换；
7. 碎片购买失败不会扣款或创建幽灵物品；
8. 同一物品不能同时摆放、赠送和存在于多个背包；
9. 赠送接受重试不会复制物品；
10. 原声音在新声音保存成功前保持有效；
11. 非星球成员不能获取声音访问授权；
12. 所有关键写操作具有幂等测试和权限测试。

## 16. 尚未选定的实现决策

以下选择必须在开始后端脚手架前完成，但不影响本合同：

- 数据库与迁移工具；
- 实时网关运行环境；
- 对象存储和音频处理方案；
- 登录提供方；
- Web 正式客户端继续使用 Three.js，还是由 Godot Web/原生客户端承担；
- 首个部署地区和隐私合规范围。

技术选型必须优先满足当前小规模验证、音频隐私、可迁移性和本地开发体验，不能仅因未来可能扩大而提前采用复杂分布式架构。
