# Echo Cabin Sound Creation UI Shell

**文档版本：** V0.2  
**文档状态：** 交互逻辑已冻结，待视觉稿最终确认  
**适用阶段：** Prototype 阶段 3 与阶段 4 之间的界面架构 Checkpoint

## 1. Checkpoint 目标

本 Checkpoint 冻结角色创建、已有角色声音替换和角色切换的界面结构，使阶段 4 可以在唯一、无交叉的状态模型上实现现场录音、本地导入、试听与保存。

本文件是该 Checkpoint 的交互逻辑事实来源。视觉稿可以调整字体、色彩、间距和装饰，但不得改变本文件中的状态、返回关系、数据保留和提交语义。

## 2. 设计原则

- 主场景在正常探索期间保持干净，右上角只保留轻量的当前角色头像入口；
- 创建角色与替换已有声音是两种独立模式，可以复用组件，但不能共用步骤语义和主按钮文案；
- 现场录音与本地导入是同等权重的声音来源，不使用“推荐”“备选”或“改用”措辞；
- 声音来源只选择一次；进入具体分支后，不再重复展示相同的来源选择页；
- 录音与导入成功后复用统一的候选声音试听组件；
- 同一页面只保留一个播放控制，避免重复播放按钮；
- 声音操作层内同一时间只允许一个试听播放；开始录音、切换试听对象或关闭操作层时停止当前试听；
- 所有处理中状态阻止重复提交，所有失败状态保留仍可恢复的数据；
- 桌面和移动端共享同一状态结构，桌面与横屏使用居中卡片，竖屏使用底部抽屉；
- 视觉采用温暖、轻量的游戏 UI，不使用深黑后台面板、锁定槽或会被误解为付费的反馈。

## 3. 共享数据语义

### 3.1 创建模式

创建模式维护 `creationDraft`：

- 包含经过去除首尾空格的名字、已选预设形象和可选的候选声音；
- draft 不计入 4 个正式角色容量，不占出生点，不出现在场景或角色切换列表中；
- 没有有效且主动保存的声音时不能完成角色创建；
- 保存成功后，draft 才原子提交为 active character。

### 3.2 编辑已有角色声音模式

编辑模式同时维护：

- `targetCharacterId`：打开编辑流时固定的目标角色；
- `existingSound`：角色当前正式生效的声音；
- `candidateSound`：本次重新录制或重新导入后、尚未保存的新声音。

在候选声音保存成功前，`existingSound` 始终继续生效。权限拒绝、录音取消、文件选择取消、读取或解码失败、返回、放弃候选及保存失败都不得删除或替换旧声音。只有玩家点击“替换声音”且保存成功后，系统才原子替换声音引用并释放旧资源。

替换成功不得改变角色名字、形象、位置、出生点分配或当前控制状态。

声音编辑层打开期间，目标角色固定且角色切换入口不可用；关闭编辑层后才恢复切换。任何异步录音、导入或保存结果都必须校验仍属于当前编辑会话与 `targetCharacterId`，已经取消或过期的结果不得写入角色。

当玩家已有一段候选声音，又选择重新录音、重新选择文件或更换来源时，旧候选声音继续保留，直到新候选成功生成。权限拒绝、取消录音、关闭文件选择器、读取失败或解码失败不得清除仍可试听的旧候选；新候选成功后才替换旧候选并释放旧候选资源。

## 4. 创建角色状态机

### 4.1 场景入口

- 尚无角色时显示明确的“创建第一个角色”；
- 已有角色时，从右上角头像浮层进入“添加角色”；
- 达到 `4 / 4` 时禁用添加入口并显示“已达到角色上限”；
- 不使用“邀请朋友”、锁图标、重复的加号槽位和底部添加按钮。

### 4.2 第一步：角色身份

身份页顶部显示当前步骤 `1 身份 → 2 声音`。只有身份校验通过并进入下一步后，声音页才显示 `身份 ✓ → 2 声音`。

身份页包含：

- 角色名字输入；
- 全身角色形象选择，不使用头像裁切代替形象选择；
- 当前选中形象的清晰状态；
- “下一步”和“取消创建”。

校验规则：

- 名字去除首尾空格后不能为空；
- 名字长度上限集中配置，并在超限时显示行内提示；
- 同一预设形象允许被多个角色重复使用；
- 当前只有一个形象时，仍显示为已选中的完整形象卡，并以弱提示说明后续会增加更多形象；
- 当前 Prototype 不显示 AI 生成形象入口。

### 4.3 第二步：声音来源

声音页以同等视觉权重显示两个入口：

- 现场录音；
- 本地导入。

两个入口不得使用“推荐”“备选”“改用”或主次暗示。玩家可以返回身份页，名字、形象和已存在的候选声音继续保留。

若运行时能力检测确认某一来源不可用，可以禁用该入口并说明原因；另一入口仍保持其原有名称与位置，不得被描述成“备选”或“改用”。

### 4.4 现场录音分支

```text
声音来源
→ 现场录音说明
→ 玩家点击“开始录音”
→ 请求麦克风权限
→ 录音中
→ 停止录音
→ 试听录音候选
```

规则：

- 进入录音说明时不请求权限；只有明确点击“开始录音”才请求；
- 录音说明给出建议时长，但除非另有技术规格，不强制在 5 秒自动截断；
- 录音中只显示“停止录音”和“取消录音”，隐藏通用返回；
- “停止录音”生成候选声音并进入试听；
- “取消录音”丢弃本次未完成录音并返回声音来源页，不清理名字和形象；
- 权限拒绝、无设备或录音失败时，可以重试或返回声音来源页，不显示“改用本地导入”快捷操作。

### 4.5 本地导入分支

```text
声音来源
→ 本地导入
→ 系统文件选择器
→ 文件读取与检查
→ 试听导入候选
```

规则：

- 用户主动关闭系统文件选择器不属于失败，停留或返回导入入口；
- 读取和解码期间显示处理中状态并阻止重复选择；
- 文件不支持、损坏或解码失败统一显示“无法读取这个声音文件”；
- 失败状态只提供“重新选择文件”和低强调“返回声音来源”；
- 导入失败页不显示现场录音快捷按钮。

### 4.6 候选声音试听与创建提交

录音和导入共用同一试听组件，只保留一个播放／暂停控制、进度反馈和时长。

根据候选来源显示不同的次级操作：

- 录音候选：“重新录音”；
- 导入候选：“重新选择文件”；
- 两者均可提供低强调的“更换声音来源”，返回同等权重的来源选择页。

候选声音成功生成后即启用创建模式的唯一主按钮“保存声音并创建角色”。玩家可以试听确认，也可以不试听直接保存；试听不是保存前置条件。保存中禁用退出和重复提交。保存失败时保留候选声音，提供“重新尝试保存”“返回试听”和“取消创建”；不得创建无声角色。

## 5. 已有角色声音编辑状态机

### 5.1 入口与当前声音

右上角角色头像浮层包含：

- 已有角色头像、名字和当前角色标识；
- “编辑角色声音”；
- “添加角色”；
- `N / 4 个角色`容量反馈。

点击其他角色头像后立即完成切换、收起浮层并返回场景。当前角色使用柔和外圈与勾选标识。界面不使用锁图标，也不同时放置空槽加号和重复的添加按钮。

点击“编辑角色声音”进入独立编辑流。该页面标题为“编辑角色声音”，不显示创建流程的 `身份 → 声音`数字步骤，也不暗示可以编辑名字、形象或删除角色。

页面先展示当前正式声音的试听，并提供：

- 重新录音；
- 重新导入；
- 返回场景。

选择“重新录音”后直接进入录音说明；选择“重新导入”后直接打开文件选择器。不得再插入重复的通用声音来源选择页。

### 5.2 编辑模式候选试听

录音产生的候选显示：

- 试听新声音；
- 重新录音；
- 低强调“更换声音来源”；
- 主按钮“替换声音”。

导入产生的候选显示：

- 试听新声音；
- 重新选择文件；
- 低强调“更换声音来源”；
- 主按钮“替换声音”。

不得同时把“重新录音”和“重新导入”作为同等级按钮放在同一候选页。

候选声音成功生成后即启用“替换声音”。玩家可以试听确认，也可以不试听直接替换；试听不是替换前置条件。

### 5.3 放弃、保存与失败

- 已产生候选声音时退出编辑，先确认“放弃这段尚未保存的新声音吗”；
- 放弃候选只释放 `candidateSound`，旧声音保持不变；
- 保存中禁用退出与重复提交；
- 保存成功后，候选成为正式声音，旧声音资源才被释放；
- 保存失败时旧声音继续生效，候选声音也继续保留；
- 失败文案说明“原来的声音仍在使用，新声音也已保留”；
- 失败操作为“重新尝试保存”和“返回试听”。

## 6. 返回、取消与清理

| 状态 | 返回或取消行为 |
| --- | --- |
| 身份页无有效输入 | 直接取消并清理 draft |
| 身份页已有有效输入 | 确认后放弃整个创建 draft |
| 声音来源页 | 返回身份，保留 draft 和候选声音 |
| 录音中 | 不显示返回；“取消录音”返回声音来源 |
| 文件选择器被关闭 | 不报错，回到导入入口 |
| 导入或保存处理中 | 暂时阻止退出与重复提交 |
| 创建模式候选试听 | 返回身份时保留候选；取消整个创建时确认清理 |
| 编辑模式尚无候选 | 直接返回当前声音或场景 |
| 编辑模式已有候选 | 退出前确认是否放弃候选，旧声音始终保留 |

## 7. 必须覆盖的错误状态

- 麦克风权限拒绝；
- 无可用输入设备；
- 录音失败；
- 文件格式不支持、文件损坏或音频解码失败；
- 文件读取中断；
- 创建保存失败；
- 已有角色声音替换失败。

错误状态都必须说明保留了什么、下一步能做什么，并提供明确恢复动作。不得在错误发生后悄悄清理 draft、候选声音或已有正式声音。

## 8. 布局与视觉边界

- 桌面和手机横屏使用不长期遮挡场景的居中卡片；
- 手机竖屏使用底部抽屉，确保主按钮、取消和错误恢复操作不溢出；
- 创建或编辑操作层打开时截获场景指针事件，点击卡片、遮罩或控件不得触发角色移动；
- 身份页使用全身角色形象卡，右上角角色切换入口可以使用头像；
- 创建和编辑流程均应支持键盘焦点、清晰标签与足够触摸命中区；
- 状态不能只靠颜色表达，当前步骤、当前角色、错误与禁用状态需有文字或图形辅助；
- 当前不制作完整 Design System、正式动画、最终字体和全套高保真页面。

## 9. Checkpoint 完成门槛

以下条件全部满足后，才允许进入阶段 4：

- 创建模式与编辑已有声音模式在标题、步骤、主按钮和数据语义上完全区分；
- 身份页使用全身形象选择，当前步骤显示正确；
- 现场录音和本地导入同等权重，所有界面均无“改用”暗示；
- 录音中没有重复的返回／取消操作；
- 试听页只有一个播放控制，并按来源显示正确的重新操作；
- 导入失败只有重新选择与返回声音来源；
- 文件选择器取消不被当作错误；
- 创建保存失败保留 candidate，且不创建无声角色；
- 编辑失败同时保留 existingSound 与 candidateSound；
- 已有角色声音可以重新录制或重新导入并原子替换；
- 角色切换后立即返回场景，位置和声音身份按上游规则重算；
- 编辑层打开时固定目标角色并阻止角色切换，取消后的迟到异步结果不会写入任何角色；
- `4 / 4` 时禁用添加角色，界面无锁图标和重复添加入口；
- 桌面横屏、移动横屏和竖屏底部抽屉均可走通关键流程；
- 未实现阶段 4 代码，也未扩展名字／形象编辑、删除角色、AI 生成或高级音频编辑。

## 10. 提交前逻辑自审清单

提交 UI 或阶段 4 实现前，必须逐项检查：

1. 当前页面属于创建还是编辑模式，是否出现了另一模式的步骤条或主按钮；
2. 声音来源是否被重复选择；
3. 录音与导入是否被错误做成主次关系；
4. 录音、导入、试听、保存中是否存在重复操作或无出口状态；
5. 返回、取消、关闭和失败分别保留或清理哪些数据；
6. 旧声音是否可能在替换成功前丢失；
7. candidate 是否可能在保存失败后丢失；
8. 文件选择器取消是否被误报为失败；
9. 快速重复点击是否可能触发两次保存、创建或替换；
10. 角色数量、出生点、位置和当前控制状态是否会被声音编辑误改；
11. 文案是否仍出现“邀请朋友”“改用”“保存并完成”“编辑当前角色”等越界或含糊表述；
12. 手机横屏、竖屏、键盘焦点和触摸命中区是否存在无法完成的路径。
13. 试听、开始录音、关闭操作层或切换状态时，是否可能残留多个同时播放的预览声音。
