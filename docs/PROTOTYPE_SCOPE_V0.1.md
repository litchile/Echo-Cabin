# Echo Cabin 核心交互原型范围

**文档版本：** V0.1  
**文档状态：** 本轮原型唯一实现事实来源  
**适用范围：** 仅适用于当前公开可访问的核心交互原型

## 1. 文档职责

本文件是本轮 Echo Cabin 核心交互原型的唯一实现事实来源。实现、测试和验收均以本文件为准，不通过 Game Bible 的文件名、正文版本号或完成状态推断本轮需求。

本文件只收窄本轮验证范围，不修改、覆盖或废止 Project Charter、Game Bible 和 UX Flow。原型验证结束后，再决定是否将验证结果同步到上游产品文档。

## 2. 本轮目标

本轮只验证以下核心体验是否成立：

- 玩家可以在一个固定房间内移动；
- 房间内有两个固定的声音角色；
- 两个角色的循环声音根据玩家与角色之间的距离连续、非线性衰减；
- 玩家进入一个固定回忆物品的交互范围后，可以主动点击并听完一段完整语音；
- 回忆物品播放期间，两个角色的循环声音平滑降低，播放结束后平滑恢复；
- 原型可以通过公开链接访问，并可在目标桌面与移动浏览器中完成验证。

本轮目标不是制作完整游戏，也不是验证完整的新手流程、内容生产流程、社交系统或最终视觉风格。

## 3. 纳入功能

### 3.1 固定场景

- 只使用一个固定房间；
- 房间边界和可移动区域固定；
- 玩家、两个声音角色和一个回忆物品使用预设位置；
- 场景不切换，不支持多房间；
- 页面应阻止滚动和回弹干扰场景操作。

### 3.2 玩家移动

- 玩家通过明确点击或触摸房间内的合法位置设置移动目标；
- 玩家角色自动向目标位置移动；
- 点击或触摸新的合法位置时，可以更新移动目标；
- 玩家不能移动到房间边界之外；
- 所有移动操作必须同时支持鼠标和触摸；
- 交互不得依赖 `hover`；
- 场景交互区域应设置 `touch-action: none`；
- 页面应设置 `overscroll-behavior: none`。

### 3.3 两个角色的距离声音

- 房间内固定放置两个声音角色；
- 两个角色分别绑定一段由项目方提供的临时录音；
- 两个角色的声音循环播放；
- 每个角色的音量只根据玩家与该角色之间的场景距离计算；
- 距离衰减必须连续且为非线性，不使用突然切换音量的分段开关；
- 距离小于或等于完全清晰距离时，使用该角色允许的最大音量；
- 距离达到或超过最大听觉距离时，该角色音量降为零；
- 两个角色可以同时被听见。

本轮固定音频参数：

| 参数 | 数值 |
| --- | ---: |
| 最大听觉距离 | 420 px |
| 完全清晰距离 | 80 px |
| 单角色最大音量 | 0.45 |
| 回忆物品播放时角色音量比例 | 0.22 |
| 淡入淡出时间 | 250–400 ms |

补充约束：

- 任意单角色循环声音的音量不得达到 `1.0`；
- 两个角色同时处于最近距离时，应保留至少约 6 dB 的总增益余量；
- 第一版不引入 compressor；
- 第一版只通过单声源音量上限和 master gain 控制总输出余量；
- 角色声音的开始、停止、距离变化、降低和恢复均应使用平滑增益变化，避免爆音和明显跳变。

### 3.4 回忆物品交互

回忆物品交互以以下状态和规则为准：

1. 玩家进入物品交互范围后，物品显示可交互状态或提示；
2. 进入交互范围不会自动播放语音；
3. 只有玩家位于交互范围内并主动点击或触摸物品，才开始播放；
4. 一旦播放开始，即使玩家随后离开交互范围，语音仍继续播放至自然结束；
5. 播放期间不允许重复触发同一段物品语音；
6. 播放结束后，玩家需要再次位于交互范围内并主动点击或触摸物品，才能再次播放；
7. 玩家离开交互范围后，物品的可交互状态或提示消失，但不影响已经开始的播放；
8. 物品语音每次均从头播放，不保留上次播放进度。

### 3.5 音频优先级

- 回忆物品语音开始播放时，两个角色当时的距离音量应在 250–400 ms 内平滑降低至原目标音量的 `0.22`；
- 回忆物品语音播放期间，角色仍继续遵循距离计算，但最终输出乘以 `0.22`；
- 回忆物品语音自然结束后，两个角色声音在 250–400 ms 内平滑恢复到届时距离对应的目标音量；
- 物品播放期间不得再次触发物品语音；
- 第一版不要求物品语音也根据距离改变音量。

### 3.6 音频初始化和恢复

- 页面加载时不得自动创建并播放角色循环音频；
- 所有音频初始化必须绑定到用户第一次明确点击或触摸“开始体验”；
- 在用户点击或触摸“开始体验”前，不启动角色循环声音；
- 初始化时应检查并处理 `AudioContext` 的 `suspended` 状态；
- 页面切到后台再返回后，如果浏览器挂起音频，应向用户提供再次点击恢复声音的入口；
- 本轮不承诺锁屏继续播放；
- 本轮不承诺后台音频；
- 本轮不绕过浏览器的自动播放限制。

## 4. 视觉资产边界

- 场景、玩家角色、两个声音角色和回忆物品均使用外部视觉资产；
- 实现时可以复用现有探索态低保真 SVG 的画布比例、空间关系和灰度布局作为占位与定位参考；
- 视觉资产应通过可替换的资源路径接入，不与交互逻辑强耦合；
- Codex 不负责生成最终美术、最终角色设计、最终物品设计或最终场景插画；
- 本轮不调整最终视觉风格，不把工程占位表现视为最终美术方案；
- 项目方负责提供或确认最终使用的视觉资产及其公开使用权限。

## 5. 音频资产边界

- 本轮共使用三段由项目方自行录制并提供的临时声音：两个角色循环声音和一段回忆物品完整语音；
- Codex 不从互联网下载或替换临时音频；
- 音频文件应作为可替换的外部资源接入；
- 项目方负责确认音频内容、格式、音量基础质量和公开访问授权。

## 6. 不纳入功能

本轮明确不实现：

- 录音上传、文件导入、试听编辑和声音保存；
- 家具或回忆物品新增、移动、删除和摆放；
- 多人在线、实时同步和邀请加入；
- 账号、登录、身份和权限系统；
- 本地或云端存档；
- 多房间、场景切换和自由世界；
- 角色创建和角色切换；
- 后端服务和数据库；
- 任务、剧情、NPC、收集和经营系统；
- 锁屏播放和后台音频；
- compressor 或复杂的动态范围处理；
- 最终美术生产和最终视觉风格调整。

## 7. 部署与资源路径

- 原型以静态 Web 应用形式部署到 GitHub Pages；
- 所有资源路径必须兼容 GitHub Pages 的仓库子路径；
- 不得使用会指向域名根目录的 `/assets/...` 路径；
- 应使用构建工具提供的 base URL 或正确的相对路径；
- 如果使用 Vite，应根据仓库名 `Echo-Cabin` 配置适用于 GitHub Pages 的 base，并在实际部署结果中验证；
- 不仅要验证首次从公开链接进入，还要验证子路径页面刷新后的资源加载。

部署后必须验证：

- 背景或场景视觉资产可以加载；
- 玩家和两个声音角色的视觉资产可以加载；
- 回忆物品视觉资产可以加载；
- 三段音频都可以加载并播放；
- 直接打开公开链接正常；
- 刷新页面后仍正常；
- 音频初始化和恢复入口正常。

## 8. 浏览器与移动端承诺

本轮至少测试：

- iPhone Safari；
- Android Chrome；
- 桌面 Chrome。

移动端实现要求：

- 所有核心操作支持 `touch`；
- 不依赖 `hover` 才能发现或完成操作；
- 场景操作时页面不滚动、不缩放回弹干扰移动；
- 正确处理 `AudioContext` 的 `suspended` 状态；
- 从后台返回后，允许用户通过明确点击恢复声音；
- 不要求锁屏或后台持续播放。

如果开发环境没有 iPhone，公开链接发布后应由持有 iPhone 的测试者完成 Safari 实机验证。在此之前，只能将代码级兼容性检查标记为完成，不能替代实机验收。

## 9. 验收标准

以下条件全部满足时，本轮核心交互原型才视为通过：

1. 页面打开后不会自动播放声音；
2. 用户明确点击或触摸“开始体验”后，音频才初始化并开始角色循环；
3. 玩家可以通过鼠标或触摸在固定房间内移动，且页面滚动不会干扰移动；
4. 两个角色保持固定位置；
5. 玩家靠近任一角色时，对应声音连续、非线性增大；
6. 玩家远离任一角色时，对应声音连续减小，并在 420 px 及以外归零；
7. 单个角色最大音量不超过 0.45，且任意情况下不会达到 1.0；
8. 两个角色同时最近时仍保留约 6 dB 总增益余量；
9. 玩家进入物品交互范围后能看到可交互提示，但不会自动播放；
10. 玩家只有在交互范围内主动点击或触摸物品后，物品语音才开始；
11. 物品语音开始后，玩家离开范围不会中断播放；
12. 物品语音播放期间不能重复触发；
13. 物品语音播放期间，角色声音平滑降低至其距离目标音量的 0.22；
14. 物品语音自然结束后，角色声音平滑恢复到当前距离对应的音量；
15. 物品播放结束后，玩家再次位于范围内并主动点击时可以再次完整播放；
16. 淡入、淡出、降低和恢复在 250–400 ms 内完成且无明显爆音；
17. GitHub Pages 公开链接可以访问，刷新后视觉和音频资源仍能加载；
18. iPhone Safari、Android Chrome 和桌面 Chrome 均完成核心流程验证。

## 10. 与现有文档暂时不一致的规则

以下差异为已知且有意保留的临时产品决策：

1. Game Bible 当前规定玩家离开物品交互范围后，物品声音快速淡出并停止；
2. 本轮原型改为：玩家在交互范围内主动触发后，物品语音完整播放，即使玩家离开范围也不中断；
3. Game Bible 的文件名、正文版本号和文档完成状态目前存在不一致；
4. 本轮实现不依据上述版本标识推断需求，只依据本文件；
5. 本轮暂不修改 Game Bible，也不覆盖其中的长期产品规则；
6. 待核心原型完成验证后，再统一决定并同步 Game Bible、UX Flow 和其他相关产品文档。
