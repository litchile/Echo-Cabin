# Echo Cabin 核心声音交互 Web Prototype 实现计划

**文档版本：** V0.3  
**文档状态：** 已冻结，可用于分阶段实现与逐项验收  
**上游文档：** Project Charter V0.9、Game Bible V0.10、UX Flow V0.5、Prototype Scope V0.3  
**适用范围：** 当前核心声音交互 Web Prototype，不包含正式 Demo 技术架构

## 1. 计划目标

本计划将冻结文档转换为可以逐项实现、验证和停止扩张的工程顺序。每一步只有在本步验收通过后才进入下一步；未通过时只修复当前模块，不提前并行堆叠后续功能。

本计划只定义模块、建议文件结构、实现顺序、验收标准、风险和依赖，不代表已经开始编码。

## 2. 实施原则

- 使用静态 Web 应用作为一次性验证壳；
- 建议采用 Vite + TypeScript，不引入前端 UI 框架；
- 场景使用 DOM 舞台与绝对定位精灵，界面层使用普通 DOM；
- 所有世界逻辑使用 `1920 × 1080` 虚拟坐标，禁止直接使用 CSS 像素计算距离；
- 视觉、音频、坐标和增益通过集中配置接入；
- Web Audio、角色状态、场景移动和界面状态彼此分离；
- 不为账号、服务器、多人同步、CMS、正式存档或完整物品布置预留复杂架构；
- 每个阶段保留最小可运行状态，并记录手工验收结果；
- 移动浏览器兼容性不推迟到最后才处理：每个涉及输入或音频的阶段均做代码级移动端检查，最终阶段再完成实机验收；
- 阶段 1 和阶段 4 后分别执行公开环境冒烟测试，正式部署验收仍保留在阶段 9；
- 每个阶段必须独立验收、独立报告并停下，未经项目方明确确认，不自动进入下一阶段。

### 2.1 强制代码产出门禁

以下步骤适用于每个实现阶段，并且是产出任何代码前和交付任何代码前的强制要求，不能因任务较小而跳过。

#### 代码修改前

1. **反思模式：** 将本阶段任务逐条与 `PROTOTYPE_SCOPE_V0.3.md` 的验收标准比对，列出本阶段直接覆盖、间接影响和明确不覆盖的条目；
2. **冲突检查：** 检查当前代码和拟议修改是否违反 Project Charter V0.9、Game Bible V0.10 或 UX Flow V0.5 的核心规则；
3. **自我质疑：** 判断是否存在更简单、范围更小的实现方式，并检查是否遗漏 iPhone Safari、Android Chrome、触摸输入、音频权限、自动播放或页面生命周期限制；
4. 只有确认任务边界清楚、无文档冲突且没有更小的等价实现后，才允许修改代码。

报告完成后必须停止并等待项目方确认。不得因为本阶段通过而自行开始下一阶段。

## 3. 模块拆分

### 3.1 应用外壳

职责：页面启动、全局状态装配、模块初始化和错误兜底。

不负责：世界坐标算法、角色移动、音频计算或具体资源定义。

### 3.2 配置与资源清单

职责：集中维护场景、角色、出生点、回忆物品、移动边界、距离参数、增益参数、淡入淡出时间和资源路径。

不负责：加载流程和运行时状态。

### 3.3 虚拟舞台与坐标转换

职责：保持 `1920 × 1080` 比例、计算画布有效区域、处理留白、完成页面坐标与世界坐标互转。

不负责：决定点击目标是否合法。

### 3.4 场景与移动

职责：加载场景资源、维护合法移动区域、接收世界坐标目标、更新当前角色位置、处理中途改目标和到达停止。

不负责：角色创建或音频播放。

### 3.5 角色领域状态

职责：区分创建中的 draft character 与正式 active character，维护最多 4 个正式角色的数据、出生点分配、当前角色身份、角色切换及位置保留。

不负责：录制实现或音频节点生命周期。

### 3.6 角色创建与声音采集

职责：角色身份、等权声音来源选择、现场录制、本地导入、统一试听、创建提交、已有角色声音原子替换及错误恢复。

不负责：距离衰减和间歇调度。

### 3.7 音频引擎

职责：统一 AudioContext、角色长期音频通道与独立 gain、Character Bus、Memory Bus、Master、平滑增益和资源解码。每次实际播放创建新的 source，不能复用已经播放结束的 source。

不负责：决定何时播放下一次角色声音。

### 3.8 空间混音

职责：固定自声、其他角色距离计算、smoothstep 衰减、角色切换后的身份重算和世界位置变化后的目标增益更新。

### 3.9 间歇播放调度

职责：每个角色独立执行“播放 → 随机静默 1—3 秒 → 再次播放”，处理首次偏移、离开听觉范围和恢复。

### 3.10 回忆物品

职责：150/165 范围迟滞、提示状态、点击命中、完整播放、防重复触发和播放结束复位。

### 3.11 音频焦点与恢复

职责：物品播放期间的 `0.22` 音频避让、结束恢复、页面前后台状态、AudioContext 挂起检测和用户恢复入口。

### 3.12 部署与验收

职责：GitHub Pages 子路径、构建产物、公开链接、刷新、资源加载和桌面/移动端测试记录。

## 5. 实现顺序与逐项验收

## 阶段 1：Web 工程骨架与虚拟画布

### 实现内容

1. 建立 Vite + TypeScript 静态工程；
2. 建立最小应用入口、全局样式和错误提示；
3. 创建 `1920 × 1080` 舞台容器并等比缩放；
4. 计算有效显示区域、缩放值和留白；
5. 实现页面坐标与世界坐标互转；
6. 设置 `touch-action: none` 与 `overscroll-behavior: none`；
7. 增加横屏优先提示，但不在竖屏时破坏页面基本操作；
8. 完成本阶段验收后发布最小公开冒烟构建，只包含虚拟画布和一张静态测试图片。

### 验收标准

- 桌面窗口、窄屏窗口和移动端视口均保持 16:9，不产生非等比拉伸；
- 点击舞台四角和中心时，转换结果分别接近 `(0,0)`、`(1920,0)`、`(0,1080)`、`(1920,1080)` 和 `(960,540)`；
- 点击 letterbox 留白不会产生世界坐标目标；
- 页面在场景区域拖动时不滚动、不回弹；
- 坐标转换具有自动化单元测试；
- 本阶段不加载角色、不初始化 AudioContext；
- GitHub Pages 最小冒烟链接可以直接访问和刷新；
- Pages 仓库子路径下静态图片加载正常；
- 手机横屏显示比例正确，letterbox 留白与本地结果一致。

### 依赖与风险

- 依赖：无；
- 风险：把 CSS 尺寸误当世界尺寸会污染后续全部距离计算；
- 风险：Pages base 配置和手机显示问题若延迟到正式部署才发现，会造成跨阶段返工；
- 控制：坐标模块先通过边界测试，其他模块只能接收世界坐标；阶段 1 即完成首次公开环境冒烟。

### 完成门槛

上述验收全部通过、阶段交付报告完成且项目方明确确认后，才进入阶段 2。

## 阶段 2：场景资源加载与点击目标移动

### 实现内容

1. 通过资源清单加载固定房间资产；
2. 定义合法移动区域和阻挡区域；
3. 放置一个临时当前角色精灵；
4. 接收合法世界坐标目标并按固定速度移动；
5. 支持途中更新目标、到达停止和边界限制；
6. 建立输入优先级：UI、角色和物品命中优先于场景移动。

### 验收标准

- 场景资产加载成功，失败时出现可理解的错误反馈；
- 鼠标点击和触摸均能设置移动目标；
- 移动过程中设置新目标后，角色转向新目标；
- 到达目标后停止，不在目标附近持续抖动；
- 墙体、边界、物品占用区和留白点击不启动移动；
- 点击临时角色、物品占位或 UI 不触发移动；
- 不同视口尺寸下，同一世界目标得到相同最终位置；
- 页面滚动与回弹不干扰移动。

### 依赖与风险

- 依赖：阶段 1 坐标转换稳定；
- 风险：当前美术资产的合法移动多边形可能尚未精确标定；
- 控制：第一版使用集中配置的明确边界，Playtest 后只调整配置。

### 墙前导航代理区新增约束

本规则只提高靠近踢脚线区域的点击容错，不修改角色真实可行走区域。墙面始终不可行走，角色逻辑位置、碰撞、声音距离和交互距离仍只使用角色脚底的真实世界坐标。

#### 配置与边界

- 当前房间中央后侧合法地板边界为 `floorTopY = 800`；左右两侧边界沿现有合法移动多边形的后侧折线斜升至 `Y = 940`；
- 代理区必须从同一条后侧合法移动边界派生，不维护第二套地板边界；
- 根据当前 `1920 × 1080` 场景调试画面实测，中央 `wallNavigationTopY = 570`，中央 `wallNavigationBottomY = floorTopY = 800`；实际左右边界随踢脚线折线变化；
- `wallNavigationBandHeight` 不再作为独立写死参数，而由 `wallNavigationBottomY - wallNavigationTopY` 计算，当前实测结果为 `230`；
- `wallFrontSafetyOffset = 60`；投影目标位于对应 X 的后侧合法边界向地板内侧 60 单位处；
- 最近合法点搜索半径为 `180`，采样步长为 `20`；该搜索只修正一次点击目标，不是寻路网格；
- 实测上边界、投影安全间距、局部搜索参数和调试显示开关均集中配置；
- 原先 `150`、`120–180` 和 `220–240` 均不再作为代理区规则或建议范围。

#### 点击目标映射

1. 点击当前已实际实现的 UI 或当前角色时，由对应命中处理优先接收，不进入场景移动映射；
2. 点击合法地板时，目标保持为实际点击世界坐标；
3. 点击由实测 `wallNavigationTopY` 与后侧边界围成的墙前代理区时，根据该 X 在现有后侧折线上的边界 Y，将目标投影为 `边界 Y + 60`；
4. 投影 X 被限制在后侧合法边界的横向范围内，投影结果必须再次通过真实可行走区域检查；
5. 投影点被固定建筑、家具或运行时物品占用区阻挡时，在半径 180 内寻找距离最近的合法地面点；
6. 合理搜索范围内没有合法点时，本次点击不更新移动目标；
7. 墙面中部、墙面上部及其他区域不响应移动；
8. 快速连续点击地板与代理区时，只更新同一个移动目标，不创建第二套移动状态。

阶段 2 的最小输入命中优先级固定为：已实际实现的 UI → 当前角色自身的必要命中 → 合法地板 → 墙前导航代理区 → 其他区域无操作。门、窗、壁龛、花瓶、盆栽和其他墙面视觉元素当前均属于场景背景，不建立独立命中层，也不阻止代理移动。回忆物品命中应在对应阶段实现时再加入；未来只有在门窗或壁龛交互获得正式确认后，才能调整其输入优先级。

#### 调试可视化

开发环境允许通过配置显示半透明调试层，包括真实可行走地板、物品可放置区域、实测墙前代理区、代理区上边界、后侧合法边界、原始点击点、直接投影点及阻挡搜索后的最终合法点。门窗、壁龛和墙面装饰不显示排除区域，因为当前没有对应命中拦截。调试层只在 `import.meta.env.DEV` 且配置开关启用时显示，生产构建必须关闭，不得进入公开体验。

#### 补充验收标准

- 点击合法地板仍移动到实际点击位置；
- 点击靠近踢脚线的代理窄带时，移动到同一横向位置对应的墙前合法地面；
- 点击代理区上边界以上的墙面中部或上部不触发移动；
- 代理区中央实测上边界为 `Y=570`、下边界为 `Y=800`，计算高度为 230；左右边界继续跟随踢脚线；
- 点击代理区内的门、中央窗户下部、右侧窗户下部、壁龛、花瓶、盆栽和其他墙面视觉元素时，均触发墙前投影；
- 点击当前角色或已实际实现的 UI 时不误触发墙前移动；
- 投影后角色脚底始终位于原有合法移动多边形内；
- 投影点被阻挡时移动到局部最近合法点，无合法点时保持原目标不变；
- 相同墙面世界坐标在不同屏幕尺寸下得到一致投影目标；
- 墙面点击不修改真实移动边界，也不把墙面坐标写入角色位置、碰撞、声音距离或交互距离；
- 开发调试层可确认代理区、后侧边界、原始点击点、投影点和阻挡回退点；
- 生产构建不显示调试遮罩；
- 鼠标与触摸使用同一目标解析规则；
- 快速连续点击地板和代理区时，目标更新稳定，无抖动或错误跳转。

本阶段不将整面墙设为移动点击区，不使用墙面百分比估算代理范围，不允许角色移动到墙面坐标，不新增寻路网格或复杂导航系统，不为墙面点击增加独立 UI，不为门窗、壁龛、墙面装饰或回忆物品建立未来交互层，也不开始阶段 3、正式角色动画或声音实现。

## 阶段 3：角色数据、创建流程与角色切换

### 实现内容

1. 定义 draft character 与 active character 两类状态；
2. draft 仅保存本次创建会话中的名字、形象和临时声音引用，不进入正式角色存储；
3. 建立最多 4 个 active character 的运行时存储；
4. 建立正式角色的未占用出生点分配；
5. 实现“角色身份”步骤：名字和预设形象；
6. 先以声音步骤接口占位，不在本阶段实现录音；
7. 建立正式角色列表和当前角色切换；
8. 切换后保留原角色位置，移动控制与聆听身份切换到新角色。

### 验收标准

- 名字和预设形象校验通过后可进入声音步骤；
- draft 不计入 4 个正式角色容量，不占用出生点、不出现在场景或切换列表中，也不作为声音来源；
- active character 数不能超过 4；
- 只有声音保存成功后，draft 才原子式转为 active character，并获得唯一 ID 和未占用合法出生位置；
- 创建取消或失败后，draft、临时资源和预留状态全部释放；
- 切换当前角色后，原角色停止响应移动且保留位置；
- 新角色接收点击目标移动；
- 快速连续切换不会产生两个同时受控角色；
- 刷新恢复不属于本轮要求，刷新后状态清空可接受；
- 当前阶段仍不得把无声音角色标记为 active character。

### 依赖与风险

- 依赖：阶段 2 的角色位置和移动接口；
- 风险：draft 提前进入正式存储会错误占用出生点、容量和切换列表；
- 风险：创建界面、运行时角色和音频节点相互强耦合；
- 控制：只有阶段 4 的声音主动保存成功才能提交 draft；active character 只保存声音引用，具体录制对象由声音采集模块管理。

## Checkpoint：Sound Creation UI Shell V0.1

阶段 3 完成后、阶段 4 编码开始前，先冻结角色创建与声音采集流程的界面结构。该 Checkpoint 只处理低保真到中保真的 UI 信息架构、状态覆盖与场景内入口关系，不实现录音、导入、音频播放或正式视觉品牌。

本 Checkpoint 的唯一设计事实来源为 `SOUND_CREATION_UI_SHELL_V0.2.md`。完成门槛是创建模式与已有角色声音编辑模式无语义交叉，核心入口、正常流程、错误状态和返回场景路径均能在原型中被连续检查，并确认主场景不会长期悬挂后台式角色管理面板。

在该 Checkpoint 确认前，不开始阶段 4 的录音与导入编码。阶段 3 已有的开发测试入口不作为公开 UI 方案，也不应进入生产体验。

## 阶段 4：现场录制、本地导入、试听与保存

### 实现内容

1. 仅在玩家进入录音说明后再次明确点击“开始录音”时请求麦克风权限；
2. 在同等视觉与交互权重下提供现场录音与本地导入，不使用“改用”或推荐暗示；
3. 实现录音说明、明确开始、停止、取消、试听、重新录音和临时资源释放；
4. 实现本地文件选择、用户取消识别、处理中防重、格式检查、解码、试听和重新选择；
5. 录音与导入复用统一候选声音试听组件，并按来源显示正确的重新操作；
6. 记录候选声音是否成功触发过试听；只有试听后主动点击“保存声音并创建角色”，声音才绑定到 draft 并完成创建；
7. 实现已有角色当前声音试听、重新录音或重新导入、候选试听与“替换声音”；
8. 以 `existingSound + candidateSound` 双引用实现原子替换，替换成功前旧声音继续生效；
9. 编辑开始时固定 `targetCharacterId`，编辑层关闭前禁用角色切换；使用会话或操作标识丢弃取消后的迟到异步结果；
10. 创建和编辑操作层截获场景输入；使用单一预览控制器确保试听、开始录音、取消与关闭时没有重叠或残留播放；
11. 处理权限拒绝、无输入设备、录制失败、文件不支持、解码失败、创建保存失败和替换保存失败；
12. 退出未保存创建流程时执行确认并清理创建 draft；退出未保存替换时只清理 candidate，不影响 existing；
13. 在明确用户交互后建立录制、导入试听所需的最小音频初始化与 `suspended` 检测，不在本阶段实现完整前后台恢复；
14. 本阶段验收通过后发布录制与导入公开冒烟构建。

### 验收标准

- 页面加载、点击“开始”以及仅进入录音说明时都不会请求麦克风权限；
- 玩家再次明确点击“开始录音”后才出现浏览器权限请求；
- 权限拒绝后可重试或返回等权声音来源，不出现“改用本地导入”快捷操作；
- 录音中只显示停止录音与取消录音，不同时显示通用返回；
- 一次录音可以停止、试听、重新录音并主动保存；
- 一次本地导入可以试听、重新选择并主动保存；用户关闭文件选择器不会进入错误页；
- 候选试听页只有一个播放控制，并按来源显示“重新录音”或“重新选择文件”；
- 已有候选后重新录音、重新选文件或更换来源时，旧候选保留到新候选成功生成；
- 未成功触发候选试听前，创建保存与替换保存按钮不可用；
- 不支持或损坏的文件不会完成角色创建；
- 创建保存失败保留 candidate，不会错误创建 active character；
- 编辑已有声音时，未保存 candidate 不会替换 existing，也不会泄漏临时 Object URL 或录音流；
- 替换保存失败同时保留 existing 与 candidate，可重试保存或返回试听；
- 替换成功只更新声音引用，不改变角色名字、形象、位置、出生点和当前控制状态；
- 编辑期间角色切换不可用，取消编辑后的异步完成结果不会写入旧目标或新当前角色；
- 创建或编辑层点击不会触发场景移动，任一时刻只有一个试听播放且退出后无残留声音；
- 角色没有已保存声音时不能完成创建；
- 声音保存成功后，draft 才转为 active character、占用出生点并进入场景；
- 桌面 Chrome、Android Chrome 和 iPhone Safari 的录制能力差异有明确降级反馈；
- HTTPS Pages 环境下，桌面 Chrome、Android Chrome 和 iPhone Safari 至少完成录制权限、停止、试听与保存冒烟；
- HTTPS Pages 环境下，本地导入和试听正常；若缺少任一移动实机，只能记录为待验收，不能宣称本冒烟节点完整通过。

### 依赖与风险

- 依赖：阶段 3 创建状态；Sound Creation UI Shell V0.2 已确认；浏览器 MediaDevices、MediaRecorder、File API 与音频解码支持；
- 高风险：Safari 支持的录音编码、文件格式和权限生命周期可能与 Chrome 不同；
- 控制：以运行时能力检测决定可用入口，不只依赖 User-Agent；通过阶段 4 的 HTTPS 公开冒烟尽早在真实 iPhone 和 Android 上测试。

## 阶段 5：自声与距离声音

### 实现内容

1. 复用并完善明确用户交互后初始化的统一 AudioContext，建立最小 `suspended` 检测与 `resume()` 能力；
2. 为每个 active character 维护长期存在的独立音频通道、GainNode 和调度状态；
3. 每次角色声音实际播放时创建新的 source，连接到该角色的固定 gain 通道；播放结束后的 source 立即释放，不尝试再次启动或复用；
4. 当前角色使用固定自声目标 `0.20`；
5. 其他角色按世界距离使用 `80/420` 和 smoothstep 计算目标增益；
6. 使用 250–400 ms 平滑变化，禁止直接跳变；
7. 切换角色后重算自声身份、聆听位置与全部距离增益；
8. Character Bus 初始 gain 在 `0.40–0.50` 内按素材校准。

### 验收标准

- 当前角色自声可听且不使用零距离最大增益；
- 同一角色可以多次播放声音，每次使用新的 source，长期 gain 通道保持唯一且不重复连接；
- 距离 `≤80` 的其他角色目标增益为 `0.45`；
- 距离 `≥420` 的其他角色目标增益为 `0`；
- 80–420 间的测试点与冻结 smoothstep 公式一致；
- 玩家移动和角色切换时没有明显爆音或音量跳变；
- 相同世界距离在不同屏幕尺寸下产生相同目标增益；
- 至少 3 个角色混合无明显削波，建议以 4 个角色完成最密集情况测试；
- Character Bus 理论峰值约束和实际素材听感均有记录。

### 依赖与风险

- 依赖：阶段 3 角色身份、阶段 4 有效声音、阶段 1 世界坐标；
- 高风险：原始录音响度差异可能让正确增益公式仍产生错误听感；
- 控制：记录素材基础响度问题，先调整总线和配置，不临时改变距离公式。

## 阶段 6：间歇播放调度

### 实现内容

1. 每个角色建立独立调度状态；
2. 加入轻微首次播放随机偏移；
3. 每次声音自然结束后独立随机静默 1–3 秒；
4. 超出最大听觉距离的其他角色可停止当前周期；
5. 重新进入范围时开始新周期；
6. 角色切换、创建取消和页面销毁时正确取消计时器。

### 验收标准

- 所有角色都不是无缝 loop；
- 每次静默值均落在 1–3 秒范围；
- 不同角色不会因共享计时器永久同步；
- 当前角色自声持续遵循间歇周期；
- 离开和重新进入听觉范围不会叠加多个调度器；
- 快速切换角色不会导致同一声音重复播放；
- 页面卸载或创建取消后无孤立计时任务继续运行。

### 依赖与风险

- 依赖：阶段 5 音源与 gain 生命周期；
- 风险：浏览器后台会节流计时器；
- 控制：调度器使用明确状态与可取消句柄，恢复时根据当前状态重新对齐，不假设计时器精确运行。

## 阶段 7：回忆物品交互与音频避让

### 实现内容

1. 从配置加载一个固定回忆物品；
2. 用脚底中心和物品锚点计算距离；
3. 实现 `≤150` 进入、`>165` 离开与中间迟滞；
4. 范围内显示提示，主动命中物品才从头播放；
5. 播放开始后离开范围不停止；
6. 播放期间禁止重复触发和抢占；
7. 全部角色最终输出平滑乘以 `0.22`；
8. 自然结束后按当时角色身份与距离恢复。

### 验收标准

- 进入范围只显示提示，不自动播放；
- 在 150/165 边界往返时提示不闪烁；
- 范围内点击物品后从头播放；
- 点击提示文字之外的场景不会误触物品；
- 播放期间离开范围，语音仍自然结束；
- 播放期间重复点击无效；
- 角色声音在 250–400 ms 内降低至各自目标的 `0.22`；
- 播放期间移动时，其他角色仍按新距离计算后再乘以 `0.22`；
- 播放结束后恢复到结束时的自声和距离目标，而不是开始播放前的旧值；
- 重复进入范围并主动点击可以再次完整播放。

### 依赖与风险

- 依赖：阶段 2 输入优先级、阶段 5 空间混音、阶段 6 调度状态；
- 风险：多个模块同时写同一个 gain 造成竞争；
- 控制：距离模块只提供基础目标，audioFocus 统一计算最终倍数并负责平滑写入。
