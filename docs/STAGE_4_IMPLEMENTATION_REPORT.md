# Echo Cabin Web Prototype 阶段 4 实现报告

**日期：** 2026-07-20  
**范围：** 现场录制、本地导入、试听、保存与已有声音替换  
**本地状态：** 代码与自动化测试通过；公开 HTTPS 与移动实机冒烟待完成

## 已实现

- 只有玩家在录音说明页再次点击“开始录音”后，才调用 `getUserMedia`；
- 使用运行时能力检测判断 `MediaRecorder` 与麦克风接口是否可用；
- 根据浏览器支持情况选择 WebM/Opus 或 MP4/AAC 等录音 MIME 类型；
- 录音支持开始、停止、取消和临时流释放；
- 本地导入使用浏览器文件选择器、File API 和 25 MB 上限；
- 导入与录音均通过统一 Web Audio 解码生成内存声音资源；
- 候选声音可以试听，也可以不试听直接保存或替换；
- 任意时刻只保留一个试听音源；
- 角色创建只有在声音引用保存成功后才提交 draft；
- 已有角色使用 `existingSound + candidateSound` 原子替换；
- 替换成功才释放旧声音，失败或退出不会改变正式声音；
- 编辑期间固定目标角色并禁用角色切换；
- 操作标识用于丢弃取消后的迟到异步结果；
- 角色创建完成后回到正式场景，原有点击移动逻辑继续工作；
- 当前只有一个正式角色形象，界面不再展示伪造的颜色变体；
- 角色图不再使用色相或饱和度滤镜。

## 技术边界

- 当前声音资源只保存在浏览器本次页面会话的内存中；
- 刷新页面后角色和声音不会保留；
- 本地导入、录音、解码和试听不需要后端；
- 云端保存、多设备同步、多人共享与正式账号体系仍不纳入本阶段；
- 完整的 AudioContext 前后台恢复属于阶段 8；
- 距离声音、自声和角色循环播放属于阶段 5–6。

## 验证结果

- `npm test`：8 个测试文件、52 条测试全部通过；
- `npm run build`：TypeScript 检查与 Vite 生产构建通过；
- 浏览器检查：身份流程、等权声音来源、录音权限前说明、本地文件控件和响应式暖色操作层可访问；
- 自动化测试新增：录音 MIME 选择、文件格式与大小判断、角色声音原子替换；
- 未自动授权或采集真实麦克风内容。
